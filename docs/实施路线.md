# 实施路线

## 当前已完成：Web MVP v0.1

- 原生 ES Modules 单页应用，无第三方运行时依赖
- 战役、内容、达人、成本和效果数据模型
- 营销战役 CRUD
- 内容/达人记录 CRUD
- CPM、CPE、CTR、CVR、CPA、ROAS、ROI
- 同平台、同记录类型的效率指数
- 总览看板与行动提示
- 数据复盘和行动状态
- CSV 模板、CSV 导入导出、JSON 备份
- Node 内置服务器
- 纯函数测试和页面渲染检查

## 下一阶段：Web v0.2

1. 把浏览器本地存储迁移到 IndexedDB，增加数据版本迁移。
2. 增加指标快照，区分 24 小时、72 小时、7 天和 30 天。
3. 增加 Excel `.xlsx` 导入导出。
4. 增加战役预算与实际花费的分周趋势。
5. 增加自定义指标权重和同行业/同粉丝层级 benchmark。
6. 增加数据异常检测：CPE 突增、转化断层、数据长期未更新。

## 第三阶段：云端版本

1. 使用 CloudBase 或 NestJS + PostgreSQL。
2. 增加登录、团队、角色和审计日志。
3. 使用签名临时链接替代公开分享。
4. 所有 AI API 密钥放在服务端。
5. 增加自动备份和导出归档。

## 第四阶段：AI 策略助手

AI 只能在数据基础上给出建议：

- 从 Brief 中提取目标、人群、卖点和约束。
- 引用历史高表现记录生成选题和内容结构。
- 对低效记录给出可验证的优化假设。
- 生成下一轮 A/B 测试方案。
- 输出时显示依据记录、样本量和缺少的数据。

## 第五阶段：微信小程序

使用 Taro + React + TypeScript，复用 Web 的领域模型和指标引擎。

第一期小程序仅做：

- 快速录入
- 核心看板
- 达人排名
- 复盘提醒
- 只读报告分享

正式发布前需要准备 AppID、主体资质、隐私政策、HTTPS 备案域名和微信平台要求的相关材料。
